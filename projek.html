Skenario Penugasan

Sebuah unit industri sekolah berencana meluncurkan sebuah server mini production lokal (VPS mandiri) yang berfungsi sebagai infrastruktur penyedia web portofolio siswa, sistem pencatatan database nilai, serta sistem pemantauan ketersediaan layanan (*uptime monitoring*). Anda ditugaskan sebagai Junior Network and System Administrator untuk membangun, mengamankan, dan menguji server tersebut dari nol (*bare-metal* / Virtual Machine) sesuai spesifikasi industri yang telah ditentukan.

⚠️ Petunjuk Pelaksanaan Praktik:
  • Praktik dikerjakan secara mandiri pada komputer/laptop masing-masing menggunakan software virtualisasi (VirtualBox / Proxmox / VMware).
  • Server wajib terhubung ke jaringan Lab TKJ melalui mode Bridged Adapter agar menerima sewa alamat IP DHCP asli dari router sekolah.
  • Dokumentasikan setiap kriteria keberhasilan penugasan dalam bentuk tangkapan layar (*screenshot*) terminal untuk dilampirkan pada laporan akhir.

Soal Tahap 1: Instalasi Sistem Operasi Headless

Pasang sistem operasi server pada mesin virtual Anda sesuai dengan spesifikasi teknis minimal produksi di bawah ini.

Spesifikasi Kebutuhan Sistem:

  • Distribusi Target: Debian GNU/Linux 12 (Bookworm) 64-bit (*Netinst ISO* atau *Standard ISO*).
  • Mode Instalasi: Teks (*Text-mode Install*), bukan Graphical Install.
  • Identitas Mesin (Hostname): Wajib menggunakan pola penamaan: srv-[namasiswa] (contoh: srv-fauzi).
  • Domain Internal: Tetapkan ke lab.wikrama.sch.id atau projek.lan.
  • Akun Administrator: Kata sandi root dibuat dengan kompleksitas yang aman.
  • Akun Pengguna Reguler: Nama akun pengguna wajib menggunakan nama Anda (misal: fauzi atau siswa).

Ketentuan Partisi Penyimpanan (Storage):

  • Gunakan sistem berkas ext4 untuk partisi root (/).
  • Alokasikan partisi swap sebesar minimal 1 GB - 2 GB.
  • Bootloader GRUB 2 wajib dipasang pada Master Boot Record drive utama (/dev/sda atau /dev/vda).
🚨 Kriteria Kegagalan: Pada tahap Tasksel (Software Selection), Anda WAJIB MENGHILANGKAN CENTANG [*] pada Debian desktop environment (GNOME/XFCE). Server yang terpasang antarmuka grafis desktop dianggap GUGUR / DISKUALIFIKASI pada aspek efisiensi memori server.

Soal Tahap 2: Konfigurasi Jaringan DHCP & Eskalasi Hak Akses

Pastikan sistem server yang baru terpasang terhubung ke jaringan laboratorium secara otomatis dan pengguna reguler memiliki wewenang administratif.

Kebutuhan Tugas:

  • Konfigurasikan antarmuka jaringan utama (contoh: eth0 atau enp0s3) di berkas /etc/network/interfaces agar meminta sewa alamat IP dinamis secara otomatis melalui protokol DHCP.
  • Pastikan server memperoleh:
    • Alamat IP yang valid dari router laboratorium.
    • Subnet mask /24 yang sesuai dengan lingkungan lab.
    • Default gateway yang mengarah ke IP Router Mikrotik lab.
  • Pastikan resolver DNS pada /etc/resolv.conf dapat menerjemahkan nama domain publik.
  • Daftarkan akun pengguna non-root yang telah Anda buat ke dalam grup sudo.
🎯 Target Pengujian Siswa:
  • Perintah ip a menampilkan antarmuka jaringan aktif dengan status UP dan memiliki IP dari segmen lab sekolah.
  • Perintah ping -c 3 8.8.8.8 dan ping -c 3 debian.org menghasilkan respon 0% packet loss.
  • Pengguna reguler dapat mengeksekusi perintah sudo whoami dan menghasilkan output root.

Soal Tahap 3: Keamanan Akses Jarak Jauh (OpenSSH Server)

Konfigurasikan daemon OpenSSH agar server dapat dikelola dari laptop klien tanpa perlu berada di depan komputer server fisik secara langsung.

Kebutuhan Tugas:

  • Pastikan service OpenSSH Server (sshd) terpasang dan berstatus aktif (active running).
  • Buat pasangan kunci kriptografi asimetris modern berjenis Ed25519 (ssh-keygen -t ed25519) pada laptop klien.
  • Salin kunci publik (id_ed25519.pub) dari laptop klien ke server menggunakan utilitas transfer resmi.
  • Uji login remote dari klien hingga berhasil masuk tanpa dimintai password akun Linux.
  • Hardening Server:
    • Kunci login password root langsung (PermitRootLogin no atau prohibit-password).
    • Nonaktifkan autentikasi password teks biasa (PasswordAuthentication no) setelah login kunci terverifikasi sukses.
🎯 Target Pengujian Siswa:
  • Koneksi remote dari terminal klien (ssh [user]@[ip-server]) berhasil terhubung secara instan tanpa prompt pengisian password.
  • Percobaan login jarak jauh sebagai akun root atau login tanpa menyertakan kunci privat otomatis ditolak dengan pesan: Permission denied (publickey).

Soal Tahap 4: Web Server & Halaman Portofolio Siswa

Bangun layanan server web berbasis Nginx untuk mempublikasikan halaman profil portofolio unjuk kerja Anda.

Kebutuhan Tugas:

  • Pasang paket web server Nginx resmi dari repositori Debian.
  • Siapkan direktori dokumen web khusus di /var/www/projek/ atau /var/www/portofolio/.
  • Buat berkas beranda index.html yang memuat identitas peserta:
    • Judul: Server Produksi Mini TKJ - SMK Wikrama
    • Nama Lengkap Peserta, NIS, dan Rombel (Kelas).
    • Ringkasan status layanan server yang sedang dibangun.
  • Atur kepemilikan direktori dokumen web kepada pengguna sistem www-data:www-data dengan mode izin akses 755.
  • Konfigurasikan Server Block (Virtual Host) baru pada direktori sites-available yang mendengarkan port 80.
  • Aktifkan konfigurasi menggunakan metode symbolic link (symlink) ke sites-enabled dan pastikan validasi sintaks bebas dari galat.
  • Lakukan hardening dengan menyembunyikan informasi versi Nginx pada response header (server_tokens off;).
🎯 Target Pengujian Siswa:
  • Browser pada laptop klien dapat membuka alamat IP lab server (http://[ip-server]) dan menampilkan halaman profil siswa secara sempurna.
  • Uji header via curl -I http://[ip-server] menunjukkan status HTTP/1.1 200 OK dengan header Server: nginx (tanpa nomor rilis versi).

Soal Tahap 5: Database Server & Pengelolaan Data Siswa

Pasang dan kelola sistem basis data relasional (RDBMS) MariaDB untuk menyimpan rekaman data siswa secara terpusat.

Kebutuhan Tugas:

  • Pasang paket mariadb-server di server Anda.
  • Jalankan wizard pengamanan mariadb-secure-installation:
    • Hapus akun pengguna anonim (*anonymous users*).
    • Nonaktifkan login remote untuk superuser root (*disallow root login remotely*).
    • Hapus database pengujian bawaan (*test database*).
    • Muat ulang tabel hak akses (*reload privilege tables*).
  • Masuk ke command line MariaDB, buat skema database baru bernama db_sekolah.
  • Buat tabel bernama siswa dengan kolom:
    • id : INT, Primary Key, Auto Increment.
    • nis : VARCHAR(10), Not Null.
    • nama : VARCHAR(50), Not Null.
    • kelas : VARCHAR(20), Not Null.
  • Masukkan minimal 3 (tiga) baris data siswa ke dalam tabel tersebut.
  • Buat akun pengguna database khusus aplikasi (misal: admin_sekolah) yang memiliki wewenang penuh atas database db_sekolah.
  • Lakukan pencadangan struktur dan data database menjadi berkas cadangan SQL (backup_sekolah.sql).
🎯 Target Pengujian Siswa:
  • Perintah SQL SELECT * FROM db_sekolah.siswa; menampilkan data tabel secara utuh dan terstruktur.
  • Berkas backup_sekolah.sql tersimpan pada direktori home pengguna dan memuat instruksi DDL/DML lengkap.

Soal Tahap 6: Keamanan Jaringan (Firewall UFW & IPS Fail2ban)

Bungkus seluruh layanan server Anda di dalam benteng pertahanan lapis ganda: pembatasan port via UFW dan pencegahan intrusi brute-force via Fail2ban.

Kebutuhan Tugas:

  • Pasang paket ufw dan fail2ban.
  • Konfigurasi Firewall UFW:
    • Terapkan kebijakan bawaan: default deny incoming dan default allow outgoing.
    • Buka izin port SSH (22 atau port kustom Anda).
    • Terapkan pembatasan frekuensi koneksi (*rate limiting*) pada port SSH.
    • Buka izin port HTTP (80/tcp) untuk akses web profil.
    • ISOLASI PORT DATABASE: Pastikan port 3306 TIDAK DIBUKA ke publik. Jika dibutuhkan, batasi hanya untuk IP tertentu.
    • Aktifkan firewall dan pastikan status bertuliskan active.
  • Konfigurasi IPS Fail2ban:
    • Buat salinan konfigurasi lokal pada /etc/fail2ban/jail.local.
    • Aktifkan jail [sshd] dengan parameter: maxretry = 3 dan bantime = 10m.
    • Jalankan daemon dan pastikan service berstatus active (running).
🎯 Target Pengujian Siswa:
  • Perintah sudo ufw status numbered menunjukkan status aktif dengan aturan port SSH dan HTTP terbuka.
  • Pengujian port database dari laptop klien menggunakan netcat/telnet (nc -zv [ip-server] 3306) menghasilkan status Connection timed out / Refused (terbukti terlindungi dari akses publik).
  • Perintah sudo fail2ban-client status sshd menampilkan jail aktif memantau log autentikasi.

Soal Tahap 7: Sistem Pemantauan Layanan (Uptime Kuma)

Integrasikan dasbor monitoring real-time untuk memantau apakah web server, database, dan port SSH Anda beroperasi secara normal (UP) atau mengalami gangguan (DOWN).

Kebutuhan Tugas:

  • Jalankan aplikasi Uptime Kuma (menggunakan Docker container atau runtime Node.js native) yang mendengarkan pada port internal 3001.
  • Pastikan aplikasi terikat ke loopback lokal (127.0.0.1:3001) dan tidak dibuka langsung pada firewall publik.
  • Reverse Proxy Nginx dengan WebSocket:
    • Buat konfigurasi Server Block Nginx baru untuk domain lokal atau sub-path (misal: status.lan atau akses port 80).
    • Wajib mengonfigurasikan header WebSocket (Upgrade $http_upgrade; dan Connection "upgrade";) agar grafik latensi dasbor terupdate secara real-time.
  • Buka dasbor Uptime Kuma dari peramban web laptop klien, buat akun administrator pemantauan.
  • Daftarkan minimal 3 (tiga) Target Probe Monitor:
    1. Monitor Web Profil (Tipe: HTTP(s), Target: http://localhost:80).
    2. Monitor Database MariaDB (Tipe: TCP Port, Target: 127.0.0.1:3306).
    3. Monitor Remote SSH (Tipe: TCP Port, Target: 127.0.0.1:22).
  • Uji Penanganan Insiden (Downtime Simulation):
    • Hentikan sementara layanan MariaDB (systemctl stop mariadb).
    • Buktikan indikator database di dasbor Uptime Kuma berubah warna menjadi merah (DOWN).
    • Hidupkan kembali layanan MariaDB dan buktikan status pulih menjadi hijau (UP).
🎯 Target Pengujian Siswa:
  • Dasbor Uptime Kuma dapat dibuka melalui peramban laptop klien tanpa galat koneksi WebSocket.
  • Seluruh target probe layanan (Web, DB, SSH) menampilkan status operasional 100% UP.
