Bab 1. Konsep Dasar Intrusion Prevention & Fail2ban

🎯 Tujuan: Memahami perbedaan IDS vs IPS, cara Fail2ban memindai berkas log, serta mekanisme interaksi dengan firewall sistem operasi.

Apa itu Fail2ban?

Fail2ban adalah kerangka kerja perangkat lunak pencegahan intrusi (*Intrusion Prevention System / IPS*) yang bertugas melindungi server Linux dari serangan otomatis seperti *brute-force password guessing*, pemindaian port (*port scanning*), dan eksploitasi URL aplikasi web.

Alih-alih memeriksa lalu lintas paket secara langsung di layer jaringan, Fail2ban bekerja secara cerdas dengan menginspeksi berkas log sistem (seperti auth log atau access log) menggunakan ekspresi reguler (*regex*). Ketika terdeteksi pola aktivitas mencurigakan yang melampaui batas ambang, Fail2ban akan langsung memerintahkan firewall (iptables/nftables/UFW) untuk memblokir alamat IP penyerang selama jangka waktu tertentu.

Tiga Komponen Inti Fail2ban

KomponenFungsi KerjaLokasi Berkas Default
FilterBerisi aturan ekspresi reguler (regex) untuk mencocokkan baris kegagalan autentikasi di dalam berkas log./etc/fail2ban/filter.d/*.conf
ActionPerintah firewall spesifik yang dieksekusi saat IP terbukti melanggar (contoh: tambah rule iptables DROP, kirim email alert, atau panggil UFW)./etc/fail2ban/action.d/*.conf
Jail (Penjara)Kombinasi utuh antara satu Filter, satu atau lebih Action, berkas log yang dipantau, serta parameter durasi blokir (*bantime*)./etc/fail2ban/jail.conf & jail.local

Perbedaan IDS vs IPS

  • IDS (Intrusion Detection System): Hanya bersifat pasif mendeteksi dan memberi peringatan kepada administrator tanpa menghentikan serangan.
  • IPS (Intrusion Prevention System): Bersifat aktif merespons ancaman secara langsung dengan memblokir lalu lintas jahat seketika (*proactive defense*). Fail2ban adalah contoh nyata implementasi IPS host-based.

Ringkasan

Fail2ban membaca log ➔ mencocokkan filter regex ➔ menghitung batas toleransi ➔ mengeksekusi aksi blokir di firewall. Latihan: Mengapa analisis berkas log lebih hemat sumber daya CPU dibandingkan sniffing seluruh paket data mentah?

Bab 2. Instalasi & Manajemen Layanan Fail2ban

🎯 Tujuan: Mengunduh dan memasang paket Fail2ban di Debian 12, mengelola daemon systemd, serta memverifikasi status CLI client.

Pemasangan Paket di Debian 12

Di Debian 12 (Bookworm), Fail2ban dapat dipasang langsung dari repositori resmi. Layanan akan terdaftar dengan unit systemd fail2ban.service.

Perintah PerawatanFungsi Kerja
sudo apt update && sudo apt install -y fail2banMemperbarui repositori dan mengunduh paket Fail2ban beserta dependensi Python3.
sudo systemctl status fail2banMengecek apakah daemon aktif berjalan (`active (running)`) dan siap memantau log.
sudo fail2ban-client pingMemverifikasi komunikasi soket antara baris perintah dan daemon (harus merespons `Server replied: pong`).
sudo fail2ban-client versionMenampilkan nomor rilis versi Fail2ban yang terpasang di sistem.

Struktur Direktori `/etc/fail2ban/`

  • fail2ban.conf : Konfigurasi tingkat proses daemon (level logging, path socket, PID file).
  • jail.conf : Berkas cetak biru (*blueprint*) seluruh konfigurasi jail bawaan vendor. Jangan diubah langsung!
  • jail.local : Berkas kustomisasi administrator yang akan menimpa nilai bawaan `jail.conf` secara aman.
  • jail.d/ : Direktori modular untuk menaruh pecahan konfigurasi jail terpisah.

Bab 3. Hirarki Konfigurasi `jail.local` & Parameter Global

🎯 Tujuan: Memahami mengapa `jail.conf` tidak boleh diedit langsung, cara membuat `jail.local`, dan menguasai parameter `bantime`, `findtime`, `maxretry`, serta `ignoreip`.

Prinsip Penimpaan Konfigurasi (.conf vs .local)

Fail2ban membaca berkas konfigurasi secara berurutan. Berkas jail.local dibaca setelah jail.conf, sehingga setiap nilai yang didefinisikan di `.local` akan otomatis menimpa (*override*) nilai di `.conf`. Ketika sistem Debian memperbarui paket Fail2ban via `apt upgrade`, berkas `jail.conf` akan diperbarui oleh pengembang, tetapi berkas `jail.local` milik kita tetap utuh dan aman.

Empat Parameter Utama Blok `[DEFAULT]`

ParameterFungsi & Arti TeknisContoh Nilai Standar
bantimeLama waktu sebuah alamat IP diblokir oleh firewall saat terbukti melanggar batas toleransi. Format mendukung akhiran m (menit), h (jam), d (hari).bantime = 10m atau 1h
findtimeJendela waktu pemantauan. Percobaan login gagal akan dihitung jika terjadi di dalam rentang waktu ini.findtime = 10m
maxretryBatas maksimum jumlah kegagalan yang ditoleransi sebelum tindakan blokir dijatuhkan.maxretry = 3 (atau 5)
ignoreipDaftar alamat IP, subnet LAN, atau domain whitelist yang dikecualikan dari pemblokiran (misal IP komputer admin kantor atau localhost).ignoreip = 127.0.0.1/8 ::1 10.0.0.5
💡 Contoh Skenario: Dengan findtime = 10m, maxretry = 3, dan bantime = 1h, maka: jika penyerang salah memasukkan password sebanyak 3 kali dalam kurun waktu 10 menit, IP penyerang langsung diblokir selama 1 jam penuh!

Bab 4. Mengamankan Akses Remote SSH (`[sshd]`)

🎯 Tujuan: Mengaktifkan dan menyesuaikan jail proteksi SSH, mengubah port layanan yang dipantau, serta mencegah serangan brute-force massal.

Mengapa Port SSH Paling Sering Diserang?

Begitu sebuah server terhubung ke internet publik pada port 22, ribuan skrip bot otomatis akan langsung mencoba kombinasi username dan password populer (*dictionary attack* seperti `root`, `admin`, `user`). Fail2ban membaca log `/var/log/auth.log` (atau journald) dan menangkal penyerang sebelum mereka berhasil menebak password.

Struktur Blok Konfigurasi `[sshd]`

[sshd]
enabled   = true
port      = ssh
filter    = sshd
logpath   = /var/log/auth.log
maxretry  = 3
bantime   = 10m
Direktif JailKeterangan Konfigurasi
enabled = trueMengaktifkan jail SSH agar daemon Fail2ban mulai memprosesnya saat startup.
port = sshMendengarkan port standar 22 (atau nomor port custom misalnya 2222 jika port SSH telah diubah).
backend = systemdMenentukan metode pembacaan log, apakah langsung dari berkas file teks atau lewat jurnal systemd.

Bab 5. Mengamankan Web Server (Nginx & HTTP)

🎯 Tujuan: Melindungi Web Server Nginx dari crawler nakal, pemindaian celah direktori tersembunyi (*botsearch*), dan serangan HTTP auth.

Jail Khusus Web Server

Selain SSH, aplikasi web sering kali menjadi sasaran empuk pemindaian file sensitif seperti /wp-login.php, /.env, atau /phpmyadmin/. Fail2ban menyediakan filter bawaan khusus Nginx di `/etc/fail2ban/filter.d/`:

Nama Jail NginxSasaran PerlindunganLog yang Dipantau
[nginx-http-auth]Mencegah brute-force pada halaman web yang diproteksi HTTP Basic Authentication (`401 Unauthorized`)./var/log/nginx/error.log
[nginx-botsearch]Memblokir bot yang mencoba memindai URL eksploitasi umum yang menghasilkan error `404 Not Found`./var/log/nginx/access.log
[nginx-limit-req]Bekerja sama dengan modul rate-limiting Nginx untuk memblokir IP yang membombardir request melebihi batas./var/log/nginx/error.log

Bab 6. Manajemen Jail & Prosedur Unban IP

🎯 Tujuan: Menggunakan utilitas `fail2ban-client` untuk memeriksa daftar IP terblokir, menguji regex filter, dan memulihkan akses pengguna yang tidak sengaja terblokir.

Perintah Administratif `fail2ban-client`

Tindakan AdministratifSintaks PerintahKeluaran / Efek
Lihat Daftar Jail Aktifsudo fail2ban-client statusMenampilkan jumlah penjara aktif dan nama jail (contoh: `sshd`).
Cek IP yang Sedang Diblokirsudo fail2ban-client status sshdMenampilkan jumlah kegagalan dan daftar `Banned IP list: 10.0.0.10`.
Buka Blokir IP Manual (*Unban*)sudo fail2ban-client set sshd unbanip 10.0.0.10Menghapus IP dari rantai blokir firewall seketika (mengembalikan status angka 1).
Blokir IP Tertentu secara Manualsudo fail2ban-client set sshd banip 192.168.1.50Menjebloskan IP mencurigakan ke penjara tanpa menunggu batas percobaan habis.

Mengapa Prosedur Unban Wajib Dikuasai?

Dalam operasional nyata, pengguna yang sah (misalnya guru, karyawan, atau administrator sistem) terkadang salah mengingat password akun mereka berulang kali hingga akhirnya IP mereka terblokir secara otomatis. Administrator harus mampu memverifikasi identitas pengguna dan membuka blokirnya secara instan lewat perintah unbanip.

Bab 7. Analisis Log, Troubleshooting & Audit

🎯 Tujuan: Membaca berkas log Fail2ban di `/var/log/fail2ban.log`, melacak riwayat pemblokiran, dan menguji filter menggunakan `fail2ban-regex`.

Struktur Entri Log Fail2ban

Aktivitas Fail2ban dicatat secara mendetail di berkas /var/log/fail2ban.log. Entri penting meliputi:

  • [sshd] Found 10.0.0.10 - 2026-10-19 13:00:01 : Pola kegagalan login terdeteksi dari IP penyerang.
  • [sshd] Ban 10.0.0.10 : Batas maxretry terlampaui, firewall mengeksekusi blokir.
  • [sshd] Unban 10.0.0.10 : Durasi bantime berakhir (atau dilepas manual oleh admin), akses kembali dibuka.

Menguji Filter dengan `fail2ban-regex`

Sebelum menerapkan filter kustom, kamu dapat menguji apakah pola ekspresi reguler yang kamu buat berhasil menangkap baris log yang dituju tanpa galat menggunakan perintah:

fail2ban-regex /var/log/auth.log /etc/fail2ban/filter.d/sshd.conf
