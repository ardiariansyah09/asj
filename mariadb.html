Bab 1. Konsep Dasar Database Server & MariaDB

🎯 Tujuan: Memahami fungsi RDBMS, arsitektur Client-Server pada database, port standar TCP 3306, serta sejarah percabangan MariaDB dari MySQL.

Apa itu Database Server?

Database Server adalah perangkat lunak back-end yang bertugas mengelola penyimpanan, relasi, indexing, transaksi, dan integritas data secara terpusat. Aplikasi lain (seperti web server Nginx/Apache, API backend Node.js, atau aplikasi mobile) bertindak sebagai klien yang meminta data menggunakan bahasa standar SQL (Structured Query Language).

MariaDB vs MySQL: Mengapa Komunitas Memilih MariaDB?

AspekMariaDBMySQL (Oracle)
Lisensi & Filosofi100% Open Source murni (GNU GPL v2), dipimpin oleh pendiri asli MySQL (Monty Widenius).Milik Oracle Corporation dengan model lisensi ganda (Community vs Commercial Enterprise).
Default di LinuxMenjadi paket database default di Debian, Ubuntu, CentOS Stream, Arch, dan Fedora.Harus menambahkan repositori pihak ketiga (APT PPA / Oracle YUM repo).
Storage EngineMenyertakan engine modern bawaan seperti Aria (pengganti MyISAM tahan crash) dan InnoDB.Fokus utama pada InnoDB bawaan Oracle.
KompatibilitasDrop-in replacement: protokol koneksi, port 3306, struktur direktori, dan perintah klien kompatibel penuh.Standar asli SQL database relasional.

Bab 2. Instalasi & Pengamanan Instance MariaDB

🎯 Tujuan: Menginstal paket `mariadb-server` di Debian 12, mengelola daemons lewat `systemctl`, dan menjalankan wizard pengamanan awal `mariadb-secure-installation`.

Manajemen Service MariaDB di Debian 12

Di Debian 12 (Bookworm), unit layanan database terdaftar dengan nama mariadb.service (dengan alias kompatibel mysql.service).

Perintah PerawatanFungsi Kerja
sudo systemctl status mariadbMengecek apakah layanan aktif berjalan (`active running`) dan port 3306 terbuka.
sudo systemctl restart mariadbMenyalakan ulang database server untuk menerapkan perubahan berkas konfigurasi.
sudo systemctl enable mariadbMemastikan database otomatis menyala saat sistem operasi di-boot.
sudo mariadb atau sudo mysqlMasuk ke command line interaktif sebagai superuser via autentikasi socket unix.

Pengamanan Awal: `mariadb-secure-installation`

Secara default, instalasi baru menyertakan beberapa celah potensial untuk kemudahan pengujian. Skrip pengamanan mariadb-secure-installation membersihkan celah tersebut dengan:

  1. Mengatur password root atau mengunci login unix socket root.
  2. Menghapus Anonymous Users: Menonaktifkan akun tanpa nama pengguna.
  3. Disallow Root Login Remotely: Membatasi akun root hanya dapat login dari localhost server langsung.
  4. Remove Test Database: Menghapus database pengujian `test` yang dapat diakses sembarang orang.
  5. Reload Privilege Tables: Menerapkan seluruh aturan keamanan baru ke memori RAM server seketika.

Bab 3. Perintah Dasar DDL & DML SQL

🎯 Tujuan: Mengoperasikan Structured Query Language (SQL) untuk mendefinisikan skema struktur tabel (DDL) dan memanipulasi baris data (DML).

Klasifikasi Bahasa SQL

KategoriKepanjanganFungsi UtamaContoh Perintah
DDLData Definition LanguageMembuat, memodifikasi, dan menghapus objek struktur database, tabel, kolom, dan indeks.CREATE DATABASE, CREATE TABLE, DROP TABLE, ALTER TABLE
DMLData Manipulation LanguageMengisi, membaca, mengubah, dan menghapus isi baris data di dalam tabel.INSERT INTO, SELECT, UPDATE, DELETE

Kaidah Perintah SQL Penting

  • Setiap perintah SQL wajib diakhiri dengan tanda titik koma (;) sebelum menekan tombol Enter.
  • Tipe data umum: INT (angka bilangan bulat), VARCHAR(n) (teks dengan panjang maksimal n karakter), TEXT (teks panjang), DATE (tanggal YYYY-MM-DD).
  • PRIMARY KEY AUTO_INCREMENT: Menjadikan kolom sebagai nomor unik pembeda baris data yang bertambah otomatis.

Bab 4. Manajemen User & Hak Akses (Privileges)

🎯 Tujuan: Menerapkan prinsip Least Privilege dengan membuat akun pengguna database non-root khusus aplikasi dan membatasi izin akses tabel.

Mengapa Akun Root Tidak Boleh Dipakai Aplikasi Web?

Akun root memiliki hak penuh terhadap seluruh sistem database (termasuk menghapus database sistem `mysql`). Apabila kode aplikasi web memiliki kerentanan SQL Injection, peretas dapat menguasai seluruh database server. Oleh karena itu, setiap aplikasi harus memiliki akun user dan database khusus.

Format Identitas User di MariaDB

Pengguna di MariaDB diidentifikasi dengan pasangan 'nama_user'@'host_asal':

Pola Host AsalArti dan Cakupan Akses
'webuser'@'localhost'Hanya diizinkan login jika berasal dari mesin yang sama secara lokal.
'webuser'@'10.0.0.20'Hanya diizinkan login jika request jaringan berasal tepat dari IP 10.0.0.20.
'webuser'@'%'Diizinkan login dari alamat IP mana saja melalui jaringan LAN maupun internet (*wildcard*).

Tingkatan Hak Akses (Privileges)

Hak Akses (Privilege)Tindakan yang Diperbolehkan
ALL PRIVILEGESMemberikan seluruh hak akses pada level database/tabel yang ditentukan.
SELECT, INSERT, UPDATEHanya boleh membaca dan mengubah baris data tanpa hak menghapus tabel (`DROP`).
FLUSH PRIVILEGES;Memerintahkan MariaDB memuat ulang tabel otorisasi memori seketika.

Bab 5. Konfigurasi Remote Access & Firewall

🎯 Tujuan: Membuka listen address database agar dapat diakses dari server aplikasi eksternal dan mengamankan port 3306 melalui firewall UFW.

Mengapa MariaDB Menolak Koneksi Luar secara Default?

Secara default, instalasi MariaDB di Debian mengikat soket jaringan ke parameter bind-address = 127.0.0.1. Artinya, port 3306 hanya mendengarkan sinyal internal mesin (loopback interface), sehingga request jaringan dari komputer lain langsung ditolak (*Connection Refused*).

Pengaturan Berkas Konfigurasi 50-server.cnf

Untuk mengizinkan koneksi jaringan luar, ubah direktif di /etc/mysql/mariadb.conf.d/50-server.cnf:

Nilai Bind AddressDampak Jaringan
bind-address = 127.0.0.1Hanya menerima koneksi internal localhost server langsung.
bind-address = 0.0.0.0Mendengarkan seluruh antarmuka jaringan (NIC fisik, Wi-Fi, dan LAN).

Pengamanan Port 3306 dengan Firewall (UFW)

⚠️ Jangan membuka port database 3306 sembarangan ke internet publik. Di lingkungan produksi, selalu batasi subnet IP pengakses, misalnya: sudo ufw allow from 10.0.0.20 to any port 3306 proto tcp.

Bab 6. Backup & Restore Database (Dump)

🎯 Tujuan: Menggunakan utilitas `mariadb-dump` / `mysqldump` untuk menghasilkan cadangan SQL logika dan memulihkannya saat terjadi insiden kehilangan data.

Metode Cadangan: Logical Dump vs Physical Backup

KriteriaLogical Dump (`mariadb-dump`)Physical Backup (Mariabackup / File Copy)
Bentuk BerkasFile teks biasa berisi rentetan instruksi SQL (`CREATE TABLE`, `INSERT INTO`).Penyalinan blok data biner dan file tablespace mentah dari `/var/lib/mysql`.
KelebihanSangat portabel: bisa dibaca manusia, diedit, dan dipulihkan ke versi MariaDB/MySQL yang berbeda.Sangat cepat untuk database berukuran raksasa (terabyte).
Penggunaan IdealDatabase skala kecil hingga menengah, migrasi antar-server, dan backup berkala harian.Enterprise sistem dengan kapasitas data masif dan kebutuhan snapshot instan.

Sintaks Ekspor dan Impor Data

  • Backup: mariadb-dump -u [user] -p [nama_db] > file_backup.sql
  • Restore: mariadb -u [user] -p [nama_db] < file_backup.sql

Bab 7. Troubleshooting & Analisis Galat

🎯 Tujuan: Mendiagnosis penyebab umum koneksi database gagal, menangani error permission, dan memeriksa riwayat log MariaDB.

Diagnosis Masalah Umum Database

Pesan Galat / ErrorKemungkinan Akar MasalahTindakan Solusi
ERROR 1045 (28000): Access denied for userPassword salah atau user tidak memiliki hak login dari host asal (misal terdaftar sebagai `user@localhost` tetapi login dari IP remote).Periksa tabel `mysql.user` dan jalankan `GRANT ... TO 'user'@'%' IDENTIFIED BY '...'`.
ERROR 2003 (HY000): Can't connect to server (111 Connection Refused)Daemon MariaDB belum menyala atau parameter `bind-address` masih mengunci di 127.0.0.1.Cek `systemctl status mariadb` dan pastikan `bind-address = 0.0.0.0`.
ERROR 2003 (HY000): Connection timed outFirewall (UFW/iptables) memblokir port 3306 atau rute jaringan terputus.Jalankan sudo ufw status dan buka aturan port 3306 TCP.
ERROR 1049 (42000): Unknown databaseNama database belum dibuat di server atau salah ejaan (huruf besar/kecil berpengaruh di Linux).Gunakan perintah SHOW DATABASES; untuk memastikan nama database yang ada.
ℹ️ Lokasi berkas log galat MariaDB di Debian berada di /var/log/mysql/error.log. Pantau pesan log runtime menggunakan perintah sudo tail -n 20 /var/log/mysql/error.log.
