Bab 1. Konsep Dasar SSH

🎯 Tujuan: Memahami apa itu SSH, cara SSH melindungi data secara kriptografis, dan mengapa protokol lawas seperti Telnet sudah tidak aman digunakan.

Client dan Server

SSH (Secure Shell) digunakan untuk mengendalikan komputer lain dari jarak jauh melalui jaringan secara terenkripsi (RFC 4251). Server menjalankan daemon sshd yang standarnya mendengarkan di port 22 TCP. Komputer client memanfaatkan program ssh untuk menghubungi server tersebut.

Analogi: Daemon sshd bertindak layaknya petugas keamanan di pintu masuk gedung, sedangkan perintah ssh adalah tamu yang berkunjung. Petugas memeriksa identitas tamu sebelum gerbang dibuka.

Bagaimana SSH Mengamankan Data

TahapYang terjadiTujuan
1. Negosiasi AlgoritmaClient dan server menyepakati standar enkripsi yang didukung bersama.Menyepakati cipher dan hash terbaik.
2. Pertukaran Kunci (Diffie-Hellman)Kedua host menghitung rahasia bersama (shared secret) tanpa mengirimkannya lewat kabel.Menghasilkan kunci sesi simetris yang aman dari penyadapan.
3. Verifikasi Host ServerClient mencocokkan sidik jari (fingerprint) host key server.Mencegah serangan Man-in-the-Middle (MitM) dari server palsu.
4. Autentikasi PenggunaVerifikasi identitas via password atau pasangan kunci publik/privat.Membuktikan hak akses pengguna.
5. Sesi TerenkripsiData ditransmisikan menggunakan enkripsi simetris cepat dengan integritas MAC/HMAC.Menjaga kerahasiaan dan keutuhan data.
💡 Analogi Diffie-Hellman: Dua pihak mencampurkan cat rahasia masing-masing dengan cat publik yang sama, lalu bertukar campuran warna tersebut. Setelah menambahkan warna rahasianya masing-masing, warna akhir yang diperoleh keduanya identik, padahal warna rahasia murni tidak pernah diserahkan satu sama lain.

Perbandingan: Telnet, RSH, dan SSH

ProtokolPort StandarEnkripsiAutentikasiTingkat RisikoRekomendasi

Ringkasan

SSH membentuk saluran terenkripsi end-to-end antara ssh (client) dan sshd (server). Latihan: Jelaskan dengan pemahamanmu mengapa pengiriman kredensial lewat Telnet sangat berbahaya di jaringan publik.

Bab 3. Login dengan Kunci Publik

🎯 Tujuan: Mengimplementasikan autentikasi kunci publik (Public Key Authentication) tanpa password yang kebal dari serangan tebak kata sandi.
Aspek KeamananAutentikasi PasswordAutentikasi Kunci Publik (Ed25519/RSA)
MetodeMengetik karakter rahasia secara manualKriptografi asimetris (Public & Private key)
Ketahanan Brute-ForceRentan diserang dengan kamus passwordSangat kuat, secara komputasi mustahil ditebak
Data ke JaringanHash password dikirim dalam tunnelKunci privat tidak pernah keluar dari mesin client

Analogi: Kunci publik (public key) berfungsi sebagai gembok yang dapat disalin ke banyak server. Kunci privat (private key) adalah anak kuncinya yang harus disimpan rapat di komputer milikmu.

Izin Akses (Permission File) Linux yang Benar

Objek Direktori/FileMode AksesPenjelasan Keamanan
Direktori ~/.ssh700 (drwx------)Hanya pengguna pemilik yang berhak melihat dan masuk.
Kunci privat (id_ed25519)600 (-rw-------)SSH menolak bekerja jika file ini dapat dibaca oleh user lain.
Kunci publik (id_ed25519.pub)644 (-rw-r--r--)Aman dibaca siapa saja karena bersifat publik.
Daftar authorized_keys600 (-rw-------)Daftar otoritas kunci; dilarang keras dapat dimodifikasi pihak lain.

Praktik di Terminal

💡 Format kunci modern yang direkomendasikan adalah Ed25519 karena cepat dan aman. Bila memerlukan format legacy RSA, gunakan panjang minimal 4096-bit (ssh-keygen -t rsa -b 4096).

Bab 4. Mengamankan SSH (Hardening)

🎯 Tujuan: Memperkuat pertahanan server SSH terhadap ancaman brute-force dan pemindaian bot otomatis di internet.
⚠️ Selalu pastikan login berbasis kunci telah teruji berhasil sebelum menonaktifkan PasswordAuthentication. Jika tidak, kamu berisiko terkunci dari server. Pada simulasi, gunakan reset jika terkunci.
Tindakan HardeningManfaat & Proteksi
PermitRootLogin noMencegah penyerang langsung menargetkan akun berkekuasaan tertinggi (root).
PasswordAuthentication noMengeliminasi 100% risiko serangan tebak password kamus otomatis.
Ubah Port Default (misal 2222) + Firewall (UFW)Menghindari bot scanner otomatis yang menyisir port default 22 di internet.
AllowUsers siswaMembatasi akses whitelist hanya untuk akun yang memang berhak login.
Memasang Fail2banMemantau kegagalan login berulang dan memblokir IP penyerang secara otomatis.

Bab 6. Tunnel & File Config

🎯 Tujuan: Mengakses layanan internal jaringan yang terisolasi lewat SSH Port Forwarding dan membuat shortcut di client via berkas ~/.ssh/config.

SSH Tunnel (Port Forwarding)

Tunneling menyalurkan lalu lintas TCP tertentu melalui sambungan SSH yang aman. Contoh skenario: Service basis data di host db diblokir dari akses luar, namun dapat dijangkau oleh server1. Melalui tunnel, client bisa mengaksesnya secara lokal.

Tipe Port ForwardingMekanisme KerjaKasus Penggunaan Nyata
-L (Local Forwarding)Membuka port di mesin client dan meneruskannya ke host tujuan via remote server.Membuka port MySQL/PostgreSQL server privat langsung dari laptop.
-R (Remote Forwarding)Membuka port di remote server dan meneruskannya balik ke layanan di client.Mengekspos web lokal port 80 ke server internet untuk sesi demo.
-D (Dynamic Forwarding)Membuka port lokal client sebagai proxy SOCKS5 terowongan penuh.Browsing internet aman melalui jaringan server.

Bab 7. Troubleshooting & Log

🎯 Tujuan: Mendiagnosis kendala koneksi SSH, memahami kode galat (error), dan mengaudit jejak login di sistem.
Pesan GalatKemungkinan Akar MasalahSolusi Rekomendasi
Connection refusedDaemon sshd tidak berjalan atau salah menentukan nomor port.Jalankan systemctl status ssh dan periksa direktif Port.
Connection timed outFirewall (UFW/iptables) memblokir port atau host offline.Buka aturan firewall dengan ufw allow.
Permission denied (publickey)Kunci publik belum terdaftar di authorized_keys atau izin direktori salah.Periksa isi dan mode izin direktori (700 untuk .ssh, 600 untuk file kunci).
Host key verification failedSidik jari host server berubah atau terindikasi serangan spoofing.Pastikan keabsahan host lalu hapus catatan usang via ssh-keygen -R host.
ℹ️ Pada Debian 12 (Bookworm), log SSH dikelola langsung oleh systemd-journald (baca dengan journalctl -u ssh). Berkas /var/log/auth.log baru aktif jika paket rsyslog dipasang.
