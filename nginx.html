Bab 1. Konsep Dasar Web Server & Nginx

🎯 Tujuan: Memahami protokol HTTP/HTTPS, cara kerja Web Server melayani klien, serta keunggulan arsitektur Asynchronous Event-Driven Nginx dibanding Apache.

Apa itu Web Server?

Web Server adalah perangkat lunak yang bertugas melayani permintaan dokumen web (HTML, CSS, gambar, API) dari browser klien melalui protokol HTTP (TCP port 80) atau HTTPS (TCP port 443). Komunikasi berjalan dengan konsep Request-Response.

Perbandingan: Nginx vs Apache HTTP Server

AspekNginx (Engine-X)Apache HTTP Server
Arsitektur DasarAsynchronous, Event-Driven, Non-blocking (1 worker process dapat menangani ribuan koneksi bersamaan).Process/Thread-based (Model MPM prefork/worker; tiap request dialokasikan thread/proses tersendiri).
Konsumsi Memori (RAM)Sangat rendah dan stabil, tidak membengkak saat lonjakan koneksi (C10K Problem Solver).Cenderung meningkat drastis seiring bertambahnya jumlah koneksi aktif.
Konten StatisSangat cepat dan efisien melayani file HTML, CSS, JS, dan berkas media langsung.Baik, namun memiliki overhead konfigurasi per-direktori (.htaccess).
Peran TambahanSangat umum difungsikan sebagai Reverse Proxy, Load Balancer, dan API Gateway.Umumnya dipakai sebagai monolithic web server terintegrasi runtime modul bawaan (mod_php).
💡 Analogi Restoran: Apache seperti restoran yang merekrut 1 pelayan khusus untuk duduk menunggui 1 meja sampai tamu selesai makan. Jika ada 100 tamu, dibutuhkan 100 pelayan (menghabiskan RAM). Nginx seperti 1 pelayan cekatan yang mencatat pesanan semua meja sekaligus sambil lalu; saat masakan siap dari dapur (event), pelayan langsung mengantarkannya ke meja yang tepat.

Kode Status HTTP Penting

Status CodeKategoriArti & Penyebab Umum
200 OKSuksesPermintaan berhasil diproses dan konten web dikirimkan ke klien.
301 / 302RedirectionHalaman dialihkan permanen (misal HTTP dipaksa pindah ke HTTPS).
403 ForbiddenClient ErrorAkses ditolak: izin baca berkas (permission) salah atau direktori tidak punya index.html.
404 Not FoundClient ErrorBerkas yang diminta di URL tidak ditemukan pada direktori `root` server.
500 Internal ErrorServer ErrorTerjadi galat pada backend program atau kesalahan fatal konfigurasi.
502 Bad GatewayServer ErrorNginx bertindak sebagai proxy, namun backend aplikasi (Node/PHP) sedang mati / tidak merespons.

Ringkasan

Nginx adalah web server modern berperforma tinggi yang melayani aset statis dengan cepat dan sering menjadi garda depan (*reverse proxy*). Latihan: Mengapa arsitektur non-blocking Nginx lebih tahan terhadap lonjakan pengunjung dibanding model proses thread?

Bab 2. Instalasi & Manajemen Layanan Nginx

🎯 Tujuan: Memasang paket Nginx di Debian 12, mengelola daemons lewat `systemctl`, dan memahami direktori default `/var/www/html`.

Manajemen Service di Debian 12

Di Debian 12 (Bookworm), Nginx dikelola melalui daemon systemd dengan unit bernama nginx.service. Setelah paket terpasang, daemon langsung aktif dan mendengarkan port 80 secara otomatis.

Perintah PerawatanFungsi Kerja
sudo systemctl status nginxMengecek apakah layanan sedang `active (running)` atau terjadi kegagalan.
sudo systemctl restart nginxMenghentikan lalu menyalakan ulang daemon (menimbulkan jeda koneksi sesaat).
sudo systemctl reload nginxMembaca ulang konfigurasi baru tanpa memutus koneksi klien yang sedang aktif (*graceful*).
sudo nginx -tMemvalidasi sintaks berkas konfigurasi sebelum diterapkan agar server tidak mogok.

Struktur Direktori Nginx

  • /etc/nginx/nginx.conf : Berkas konfigurasi global utama server.
  • /etc/nginx/sites-available/ : Wadah seluruh berkas konfigurasi virtual host/server block.
  • /etc/nginx/sites-enabled/ : Wadah symlink aktif yang dibaca langsung oleh Nginx saat berjalan.
  • /var/www/html/ : Lokasi berkas website default (dokumen root).
  • /var/log/nginx/ : Tempat penyimpanan berkas `access.log` dan `error.log`.

Bab 3. Virtual Host (Server Blocks)

🎯 Tujuan: Menghosting banyak nama domain website yang berbeda dalam satu mesin server tunggal menggunakan Server Blocks.

Konsep Name-based Virtual Hosting

Satu server fisik dengan 1 IP dapat melayani website berbeda (misal sekolah.sch.id dan portalku.lan). Saat browser menghubungi server, browser menyertakan header Host: nama_domain. Nginx memeriksa direktif server_name yang cocok lalu menyajikan dokumen dari folder root masing-masing.

Direktif KonfigurasiFungsi KonfigurasiContoh Nilai
listenPort TCP dan alamat IP yang didengarkanlisten 80;
server_nameNama domain yang dicocokkan dengan header Host klienserver_name portalku.lan;
rootFolder fisik tempat dokumen HTML website disimpanroot /var/www/portalku;
indexUrutan nama berkas utama yang dicari pertama kaliindex index.html index.htm;
💡 Mengapa menggunakan symlink (ln -s)? Direktori sites-available berfungsi sebagai gudang rancangan. Dengan membuat link ke sites-enabled, kamu dapat mengaktifkan atau menonaktifkan website dalam sekejap tanpa menghapus berkas aslinya.

Bab 4. Keamanan Web Server & Hardening

🎯 Tujuan: Mengamankan hak akses dokumen web (`www-data`), menyembunyikan identitas versi server, dan mengatur proteksi firewall (UFW).
Tindakan KeamananAlasan & Manfaat Proteksi
Kepemilikan Akun `www-data`Nginx berjalan di bawah akun non-root (`www-data`). Berkas web tidak boleh dimiliki root agar jika terjadi eksploitasi, peretas tidak langsung menguasai sistem operasi.
server_tokens off;Menyembunyikan informasi nomor versi Nginx dari response header HTTP (mempersulit pencarian kerentanan spesifik).
Firewall `ufw allow 80/tcp` & `443/tcp`Hanya membuka port 80 (HTTP) dan 443 (HTTPS), menutup port lain yang tidak berizin.
Izin Berkas 644 dan Folder 755Mencegah pengguna luar atau script nakal mengubah isi kode website tanpa izin.

Bab 5. Konfigurasi Reverse Proxy

🎯 Tujuan: Menjadikan Nginx sebagai pintu gerbang (*front-facing server*) yang meneruskan request klien ke aplikasi backend di server internal.

Apa itu Reverse Proxy?

Bila Forward Proxy bertindak mewakili klien untuk mengakses internet, maka Reverse Proxy bertindak mewakili server internal agar dapat diakses klien luar. Aplikasi modern (seperti Node.js, Python Flask/Django, Go) umumnya berjalan di port lokal (misal `127.0.0.1:8080`). Nginx menerima request di port 80/443 lalu meneruskannya via direktif proxy_pass.

Direktif ProxyFungsi dan Parameter
proxy_pass http://10.0.0.30:8080;Meneruskan lalu lintas HTTP ke server tujuan di internal localhost/jaringan privat.
proxy_set_header Host $host;Menyampaikan nama host asli yang diminta browser klien ke aplikasi backend.
proxy_set_header X-Real-IP $remote_addr;Meneruskan alamat IP asli pengunjung ke backend (agar pencatatan IP tidak tertulis IP Nginx).

Bab 6. Enkripsi HTTPS & Sertifikat SSL

🎯 Tujuan: Mengamankan transmisi data website dari penyadapan (sniffing) dengan sertifikat SSL/TLS pada port 443.

Perbedaan HTTP dan HTTPS

HTTP mentransmisikan data dalam bentuk teks biasa (plaintext), sehingga kredensial login atau formulir mudah disadap di jaringan publik. HTTPS membungkus komunikasi HTTP di dalam terowongan terenkripsi TLS menggunakan kriptografi asimetris dan simetris.

Komponen SertifikatFungsi Teknis
Private Key (nginx-selfsigned.key)Kunci rahasia milik server, tidak boleh diberikan ke pihak mana pun. Disimpan dengan permission ketat (600).
Public Certificate (nginx-selfsigned.crt)Sertifikat publik berisi identitas domain dan public key server yang dibagikan ke browser pengunjung.
Port StandarHTTPS beroperasi pada protokol TCP port 443.
