Bab 1. Konsep Dasar Firewall & UFW

🎯 Tujuan: Memahami mekanisme packet filtering, perbedaan arah lalu lintas (Inbound vs Outbound), serta posisi UFW di atas kernel netfilter Linux.

Apa itu Firewall dan UFW?

Firewall adalah sistem keamanan jaringan yang mengawasi dan menyaring lalu lintas data masuk (*inbound*) dan keluar (*outbound*) berdasarkan seperangkat aturan yang telah ditentukan. Di sistem operasi Linux Debian, penyaringan paket sebenarnya dilakukan di tingkat kernel oleh subsistem Netfilter / iptables / nftables.

UFW (Uncomplicated Firewall) hadir sebagai program baris perintah (CLI) yang membungkus sintaks rumit iptables menjadi instruksi yang sangat mudah dipahami oleh administrator sistem.

Perbandingan: UFW vs iptables Murni

Tindakan / FiturSintaks UFW (User-Friendly)Sintaks iptables Tradisional
Buka Port Web 80 TCPsudo ufw allow 80/tcpsudo iptables -A INPUT -p tcp --dport 80 -j ACCEPT
Batasi Akses dari Subnet IPsudo ufw allow from 10.0.0.0/24 to any port 22sudo iptables -A INPUT -p tcp -s 10.0.0.0/24 --dport 22 -j ACCEPT
Lihat Status & Nomor Urutsudo ufw status numberedsudo iptables -L INPUT -v -n --line-numbers

Arah Lalu Lintas: Inbound vs Outbound

  • Incoming (Inbound): Paket data yang datang dari luar menuju ke server kita (contoh: pengunjung mengakses web, admin login SSH). Ini adalah arah utama yang wajib dijaga ketat.
  • Outgoing (Outbound): Paket data yang berasal dari server menuju ke luar internet (contoh: server melakukan `apt update` atau mengunduh paket). Secara umum dibiarkan terbuka (*allow*).

Ringkasan

UFW menyederhanakan konfigurasi iptables tanpa mengurangi keandalan keamanan kernel Linux. Latihan: Mengapa aturan firewall default di server produksi harus memblokir semua paket masuk (*deny incoming*)?

Bab 2. Status & Kebijakan Default (Default Policy)

🎯 Tujuan: Menginstal UFW, memahami status daemon, dan menetapkan fondasi keamanan paling aman: *Deny Incoming* dan *Allow Outgoing*.

Filosofi Keamanan: Least Privilege

Prinsip pertahanan terbaik menyatakan bahwa seluruh pintu port harus tertutup secara default, kecuali port yang secara eksplisit diizinkan untuk operasional layanan server.

Kebijakan DefaultPerintah UFWDampak Keamanan
Tolak Semua Akses Masuksudo ufw default deny incomingSemua paket luar yang mengetuk port server langsung ditolak tanpa kecuali (*stealth mode*).
Izinkan Semua Akses Keluarsudo ufw default allow outgoingServer bebas mengunduh update sistem, sinkronisasi waktu NTP, dan resolve DNS luar.

Menghindari Bencana "Lockout"

⚠️ BAHAYA LOCKOUT: Jangan pernah menjalankan perintah sudo ufw enable jika kamu sedang mengelola server dari jarak jauh lewat SSH sebelum kamu membuka port SSH (`ufw allow 22/tcp`)! Jika lupa, koneksi SSH akan langsung putus dan kamu tidak bisa masuk kembali.

Bab 3. Mengatur Port & Protokol (Allow & Deny)

🎯 Tujuan: Membuka dan menutup port berbasis nomor angka, protokol transport (TCP/UDP), rentang port (*range*), dan profil aplikasi.

Spesifikasi Protokol: TCP vs UDP

Layanan server berjalan di protokol transport yang berbeda. Misalnya, web HTTP dan SSH menggunakan protokol andal terurut TCP, sedangkan layanan kueri DNS memakai protokol cepat tanpa jabat tangan UDP.

Tujuan AturanSintaks PerintahKeterangan
Buka Port Web HTTP Sajasudo ufw allow 80/tcpHanya membuka port 80 pada layer protokol TCP. Protokol UDP port 80 tetap tertutup.
Buka Port Aman HTTPSsudo ufw allow 443/tcpMembuka enkripsi SSL/TLS web server.
Buka Rentang Port (Range)sudo ufw allow 6000:6005/tcpMembuka 6 port berurutan sekaligus (6000 sampai 6005).
Tolak Port Tertentu secara Eksplisitsudo ufw deny 23/tcpMenolak tegas koneksi Telnet yang tidak aman.
Gunakan Nama Profil Layanansudo ufw allow 'Nginx Full'Membuka port 80 dan 443 sekaligus via profil bawaan aplikasi.

Bab 4. Nomor Urut Rule & Manajemen Aturan

🎯 Tujuan: Membaca status bernomor urut (`status numbered`), menghapus rule yang tidak terpakai, dan menyisipkan rule prioritas (*insert*).

Bagaimana UFW Memproses Aturan?

Firewall mengevaluasi paket data yang masuk dari baris paling atas ke baris paling bawah (*Top-to-Bottom Evaluation*). Begitu ada satu aturan yang cocok (*match*), tindakan langsung dieksekusi dan aturan di baris bawahnya diabaikan.

Perintah PerawatanFungsi Kerja
sudo ufw statusMelihat daftar aturan aktif secara ringkas.
sudo ufw status numberedMenampilkan nomor indeks pada tiap baris aturan untuk mempermudah penghapusan.
sudo ufw delete [nomor]Menghapus aturan berdasarkan nomor baris indeksnya.
sudo ufw insert 1 allow ...Menyisipkan aturan baru tepat di baris pertama agar dievaluasi dengan prioritas tertinggi.

Bab 5. Filter Berdasarkan IP & Subnet Spesifik

🎯 Tujuan: Mengisolasi layanan sensitif (seperti database MariaDB atau port manajemen SSH) agar hanya dapat diakses oleh komputer admin atau server aplikasi.

Mengapa Membuka Port untuk Semua Orang Itu Berbahaya?

Layanan seperti database MariaDB (port 3306) atau Redis (port 6379) tidak boleh dibuka untuk internet publik (`Anywhere`). Siapa pun dapat mencoba membobol kredensial login. Port database hanya boleh menerima koneksi dari server web backend.

Skenario KebutuhanSintaks Perintah UFW
Hanya 1 Komputer Tertentu yang Boleh SSHsudo ufw allow from 10.0.0.10 to any port 22 proto tcp
Satu Blok Subnet LAN Kantor yang Boleh Akses DBsudo ufw allow from 10.0.0.0/24 to any port 3306 proto tcp
Blokir Total IP Penyerang Tertentusudo ufw deny from 192.168.1.99

Bab 6. Rate Limiting (Proteksi Brute-Force)

🎯 Tujuan: Menangkal serangan otomatis tebak password pada port login menggunakan fitur bawaan `ufw limit`.

Cara Kerja `ufw limit`

Fitur limit pada UFW dirancang khusus untuk membatasi frekuensi percobaan koneksi baru. Secara default pada port TCP:

  • Jika sebuah alamat IP mencoba melakukan koneksi baru sebanyak 6 kali atau lebih dalam kurun waktu 30 detik, UFW akan langsung memblokir sementara koneksi dari IP tersebut.
  • Fitur ini sangat efektif untuk port manajemen jarak jauh seperti SSH (port 22) guna meredam skrip *botnet brute-force* tanpa perlu menginstal aplikasi pihak ketiga.
Perintah ProteksiPerbedaan dengan Allow Biasa
sudo ufw allow 22/tcpMenerima semua koneksi tanpa batas frekuensi, rentan terhadap serangan beruntun ribuan tebakan password per detik.
sudo ufw limit 22/tcpMengizinkan koneksi normal, namun langsung membekukan akses jika IP pengirim mencoba login berulang kali secara agresif.

Bab 7. Logging, Analisis Galat & Reset

🎯 Tujuan: Memeriksa berkas log firewall di `/var/log/ufw.log`, mengenali parameter paket blokir, dan melakukan prosedur reset darurat.

Struktur Berkas Log UFW

Ketika logging diaktifkan (`sudo ufw logging on`), setiap paket yang ditolak atau diizinkan akan dicatat ke berkas /var/log/ufw.log (atau di journal kernel `dmesg`).

Parameter LogArti TeknisContoh di Log
SRCSource IP: Alamat IP asal pengirim paket.SRC=10.0.0.10
DSTDestination IP: Alamat IP tujuan (server kita).DST=10.0.0.20
PROTOProtokol jaringan yang digunakan.PROTO=TCP
DPTDestination Port: Nomor port yang sedang dituju/diketuk.DPT=3306
[UFW BLOCK]Status tindakan bahwa paket tersebut resmi ditolak firewall.[UFW BLOCK] IN=eth0 OUT=...

Prosedur Reset Total

Jika kamu melakukan kesalahan konfigurasi fatal atau terkunci dari aturan yang bertabrakan, gunakan perintah sudo ufw reset untuk mengembalikan seluruh konfigurasi firewall ke kondisi kosong awal (*factory default*).
