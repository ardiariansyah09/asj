Bab 1. Konsep & Definisi Sistem Operasi Jaringan

🎯 Tujuan: Memahami definisi NOS, perbedaannya dengan OS Desktop, serta peranannya sebagai penyedia layanan terpusat.

Apa itu Sistem Operasi Jaringan (NOS)?

Sistem Operasi Jaringan (Network Operating System / NOS) adalah sistem operasi khusus yang dirancang untuk mengoordinasikan, mengelola, dan mengamankan lalu lintas data serta sumber daya perangkat keras (*hardware*) di dalam jaringan komputer. NOS menjadi jembatan antara banyak komputer klien (*clients*) dengan server pusat.

Perbedaan: OS Desktop vs Sistem Operasi Jaringan (Server)

Aspek PembedaOS Desktop (Client)Sistem Operasi Jaringan (NOS / Server)
Tujuan PenggunaanPengalaman personal satu pengguna (*single-user*), menjalankan software office, multimedia, dan game.Melayani banyak pengguna (*multi-user*) dan perangkat secara simultan tanpa antarmuka grafis berat.
Antarmuka (UI)Didominasi grafis GUI (*Graphical User Interface*) yang memakan banyak memori RAM dan GPU.Dominan CLI (*Command Line Interface* / Headless) untuk stabilitas dan efisiensi memori maksimal.
Ketersediaan (Uptime)Biasa dimatikan (*shutdown*) setiap hari setelah selesai digunakan.Dirancang hidup tanpa henti (*24/7/365*) dengan toleransi crash mendekati nol (*High Availability*).
Model KeamananIzin pengguna berfokus pada proteksi akun personal lokal.Kontrol hak akses ketat (*least privilege*), audit log mendalam, dan proteksi port layanan jaringan.

Ringkasan

NOS adalah otak dari arsitektur client-server modern. Latihan: Mengapa sistem operasi server umumnya dijalankan dalam mode CLI tanpa tampilan desktop grafis?

Bab 2. Karakteristik & Arsitektur Sistem Operasi Jaringan

🎯 Tujuan: Mengidentifikasi ciri-ciri penting NOS dan memahami struktur hirarki berkas Linux FHS (*Filesystem Hierarchy Standard*).

Karakteristik Utama NOS

  • Multi-User: Mengizinkan banyak pengguna masuk (*login*) dan menjalankan tugas secara bersamaan tanpa mengganggu satu sama lain.
  • Multi-Tasking Preemptive: Kernel server mengalokasikan waktu CPU secara adil sehingga layanan prioritas tinggi (seperti web atau database) tidak macet saat ada proses lain yang berat.
  • Manajemen Hak Akses Ketat: Pemisahan hak antara pengguna biasa (*unprivileged users*) dan administrator sistem tertinggi (*root / superuser*).
  • Arsitektur Server Headless: Server dijalankan tanpa monitor, keyboard fisik, atau GUI, sepenuhnya dikontrol lewat jaringan (remote SSH).

Standar Hirarki Berkas Linux (FHS)

Di Linux Debian 12, semua perangkat, konfigurasi, dan proses direpresentasikan sebagai berkas (*"Everything is a file"*). Sistem berkas diawali dari akar tertinggi (*root filesystem* /):

DirektoriPeran & Isi DirektoriContoh Berkas Penting
/etcTempat berkas konfigurasi sistem dan layanan jaringan server./etc/hostname, /etc/network/interfaces
/varPenyimpanan data dinamis yang sering berubah (log sistem, spool email, cache)./var/log/syslog, /var/log/auth.log
/homeDirektori kerja personal untuk masing-masing pengguna non-root./home/siswa/
/rootDirektori rumah khusus untuk superuser *root*./root/
/srvLokasi resmi penyimpanan data layanan publik (server web, FTP)./srv/www/, /srv/data/
/proc & /sysSistem berkas virtual di RAM yang memetakan status kernel dan hardware secara real-time./proc/cpuinfo, /proc/meminfo

Bab 3. Klasifikasi & Jenis-Jenis Sistem Operasi Jaringan

🎯 Tujuan: Mengelompokkan NOS berdasarkan model lisensi kode sumber dan mengenal keluarga distribusi Linux Server.

Model Lisensi: Open Source vs Proprietary

KategoriKarakteristik LisensiContoh Sistem Operasi
Open Source (Terbuka)Kode sumber terbuka bebas untuk dipelajari, dimodifikasi, dan didistribusikan. Bebas biaya lisensi per-core prosesor.Debian GNU/Linux, Ubuntu Server, Rocky Linux, AlmaLinux, Alpine Linux, FreeBSD.
Proprietary (Tertutup)Kode sumber dirahasiakan oleh vendor pemilik. Penggunaan server membutuhkan lisensi resmi (*CAL / Client Access License*).Microsoft Windows Server (2019/2022/2025).
Spesifik Perangkat JaringanNOS khusus yang tertanam pada perangkat keras router, switch, atau firewall managed.MikroTik RouterOS, Cisco IOS, VyOS, pfSense.

Keluarga Besar Distribusi Linux Server

  • Keluarga Debian: Terkenal dengan stabilitas ekstrem, siklus rilis konservatif, dan manajer paket APT / dpkg. Turunan populernya meliputi Ubuntu Server dan Proxmox VE. Debian 12 (Bookworm) adalah standar laboratorium ASJ Wikrama.
  • Keluarga Red Hat (RHEL): Standar industri korporat perbankan, menggunakan manajer paket RPM / DNF serta sistem keamanan SELinux. Variannya mencakup Rocky Linux dan AlmaLinux.
  • Keluarga Arch & Alpine: Mengusung model *rolling-release* atau footprint ultra-minimalis, sangat populer untuk lingkungan container Docker.

Bab 5. Manajemen Pengguna, Grup & Hak Akses Berkas

🎯 Tujuan: Menguasai prinsip *Least Privilege*, mengelola akun pengguna & grup, serta mengatur hak akses berkas (POSIX permissions).

Struktur Akun di Sistem Operasi Jaringan Linux

Linux membedakan akun pengguna menjadi tiga tingkatan:

  • Superuser (root - UID 0): Memiliki kekuasaan mutlak tanpa batasan. Kesalahan perintah di root dapat merusak seluruh server seketika.
  • System Accounts (UID 1–999): Akun khusus yang menjalankan service background secara mandiri tanpa login interaktif (contoh: www-data untuk Nginx, mysql untuk database).
  • Regular Users (UID 1000+): Pengguna manusia biasa (contoh: siswa). Jika butuh hak administratif, pengguna dimasukkan ke grup sudo.

Tabel Tiga Berkas Kunci Akun Linux

Lokasi BerkasFormat & Isi RekamanTingkat Privasi

/etc/shadowMenyimpan password yang di-hash dengan algoritma kriptografi modern (SHA-512).Hanya bisa dibaca root (640 / 000).
/etc/groupDaftar nama grup sistem dan anggota pengguna di dalamnya.Dapat dibaca semua orang (644).

Matriks Perhitungan Izin Akses Berkas (Chmod)

KarakterArti IzinNilai Angka BinerPada Berkas (File)Pada Direktori (Folder)

Bab 6. Manajemen Proses, Layanan & Pemantauan Sistem

🎯 Tujuan: Melacak proses yang sedang berjalan, mengontrol daemon via systemd, serta membaca kapasitas memori server.

Apa itu Proses dan Daemon?

Setiap program yang sedang dieksekusi di memori RAM disebut proses, dan ditandai oleh nomor unik PID (Process ID). Proses jaringan yang berjalan di latar belakang tanpa jendela interaktif disebut daemon (biasanya berakhiran huruf 'd', seperti `sshd`, `mariadbd`).

Bab 7. Manajemen Paket & Repositori Perangkat Lunak

🎯 Tujuan: Memahami mekanisme unduhan paket APT di Debian 12, berkas `sources.list`, dan pembaruan sistem secara aman.

Mekanisme Manajemen Paket Debian (APT)

Di lingkungan Linux modern, administrator tidak mengunduh berkas installer secara manual dari web peramban. Sistem menggunakan Package Manager (APT - Advanced Package Tool) yang secara otomatis mengunduh paket dari server repositori resmi, memvalidasi tanda tangan kriptografi GPG, dan menyelesaikan masalah dependensi antar-program.

Struktur Berkas `/etc/apt/sources.list`

Berkas ini berisi alamat URL mirror repositori Debian yang digunakan server untuk mencari paket:

deb http://deb.debian.org/debian bookworm main contrib non-free-firmware
deb http://security.debian.org/debian-security bookworm-security main
